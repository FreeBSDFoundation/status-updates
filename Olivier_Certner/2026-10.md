## **Reporting Period:** 2026-10-07 - 2026-10-13

### Power / Suspend-to-idle (S0ix) \[Laptop Project\]

Work on suspending non-BSP CPUs on suspend-to-idle while still allowing to
process GPE for wakeup.

First alternative: Bind ACPI taskqueue's threads on the BSP and then suspend all
other CPUs via `IPI_SUSPEND` with a modified handler doing an idle loop (calling
`cpu_idle()` repeatedly) on suspend-to-idle.  Goal is that GPE interrupts can
still arrive on any CPU, which then causes a `wakeup()` of the taskqueue's
threads, which will then run on the (not in idle loop) BSP.

Start working on a second alternative: A special "s2idle" (ULE) scheduler mode
where only threads that have been explicitly marked as allowed to run during
suspend-to-idle are still scheduled.  Goal here is to be able to add traces to
see which threads would like to run but are denied, in order to identify what
may wakeup CPUs.

### Scheduler

- Work on [D59988](https://reviews.freebsd.org/D59988) ("sched: New scheduler
  interface definition and implementation scheme"):
  - `kib@` objects that having the same name for multiple functions (one from
    the interface, and all its implementations in the existing schedulers) makes
    debugging harder.  Unfortunately, our `ddb(4)` does not set multiple
    breakpoints in this case.  That could be fixable, but some tests with GDB
    and a discussion with `markj@` seems to indicate that the wider ecossystem
    of ELF tools is not really ready to handle that case.  Back out on having
    same names for the implementation functions, and instead automatically add
    the name of the scheduler in them in declarations (e.g., `sched_ule_clock()`
    is ULE's implementation for the `sched_clock()` interface function).  This
    requires modifying the X macros so that they take extra parameters, then
    passed to each macro describing an interface function.
  - Create [D60167](https://reviews.freebsd.org/D60167) ("ifuncs: Have
    DEFINE_*IFUNC() macros expand the passed name"), commit.
  - Suffix fields in `struct sched_instance`, so that, e.g., the field for the
    `switch` function is `switch_p`, avoiding C reserved words, and in passing
    renaming `sched_*_sswitch()` implementations to `sched_switch()`.
  - Only list parameter types in the interface (dispatch) function declarations,
    allowing to remove the C++-specific bracketing of `struct sched_instance`.
  - Add a simple preamble showing some examples of how to find which functions
    are declared.  Finally commit.  Prepare a potential addition to the preamble
    comments (an explicit of all functions of the interface).
