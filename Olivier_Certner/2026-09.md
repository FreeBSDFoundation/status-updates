### Reviews of others' work

- VFS
  - Review [D59910](https://reviews.freebsd.org/D59910) ("stat(2): report mount
    points using st_bsdflags SFBSD_MNTROOT flag"): Ask to move the code adding
    the `SFBSD_MNTROOT` flag from after `VOP_STAT()` calls to a new
    `vop_stat_post()` function, but refused by `kib@`.  Discuss the forgotten
    case of `fhstat(2)`, and then point out the inconsistency of it not
    returning `SFBSD_MNTROOT` on a handle obtained by a lookup on a mountpoint,
    versus `stat(2)` returning it.  This is a clear design bug, easily avoidable
    as there is no actual need to limit `SFBSD_MNTROOT` to mount points (covered
    vnodes) in the case of `fhstat(2)` (for consistency, it has to be reported
    on filesystem roots (covering vnodes) as well).  Based on this, reject the
    (then) current state.  `markj` proposes a compromise where `fhstat(2)` never
    returns the flag, which `kib@` accepts.  It is surely much better to return
    no information than an inconsistent one, so approve this compromise to allow
    things to move forward.  It is a pity though, as a consistent solution
    exists and takes less than a minute to enable (test on `VIRF_MOUNTPOINT` in
    addition to `VV_ROOT`).
