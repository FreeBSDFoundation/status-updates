### Miscellaneous
#### **Summary**
Continued analyzing the blockif bounce buffer code. To my surprise I noticed
that not using a bounce buffer in those cases where it's unnecessary absolutely
kills performance. On illumos, this is because all I/O vectors given to preadv
and pwritev will cause an individual I/O operation to be performed to the raw
device, splitting one large I/O by the guest in dozens of small ones by the
host.

I presume the same is true on FreeBSD. Since using bounce buffers still seems
less than optimal I wonder whether the behaviour of preadv/pwritev on raw
devices can be improved.

### Miscellaneous
#### **Summary**
Ran into an issue with blockif when using raw device nodes on illumos:

When bhyve issues a preadv()/pwritev() with the iovecs it got from the guest,
each iovec needs to meet the alignment requirements for offset and length that
the underlying device imposes. ZVOLs apparently don't care, but sd disks do.

Apparently FreeBSD once had the same problem and implemented a workaround
in the blockif code using a bounce buffer if a geom device is being used.
The code is present in illumos but unused. While looking at making illumos
use this bounce buffer code path, I noticed that the implementation seems to
be unnecessarily pessimistic.

I'm trying to fix this, and if I succeed, this may significantly improve
the performance of blockif-backed storage in bhyve on FreeBSD when a device
node is used.
