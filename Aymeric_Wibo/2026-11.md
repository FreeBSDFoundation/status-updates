## **Reporting Period:** 2026-11-01 - 2026-11-06

**Overall Status:** On Track

### Project: Laptop S0i3 Support

#### Overall Goal

Get modern laptops (primarily AMD-based, such as the Framework) to reliably suspend to idle and reach the S0i3 deep sleep state on FreeBSD, and resume cleanly from it, so that laptops get battery life in suspend comparable to other operating systems.

#### Current Work

- **Suspend-to-idle loop:** Instead of suspending once and resuming on the first interrupt, the system needs to stay in a loop in suspend-to-idle, process events which don't need to wake the system (e.g. battery level events), and only fully resume on genuine wake events. This is the last major missing piece for suspend-to-idle support.
- **Resuming USB4 controllers:** USB4 controllers must be correctly suspended for the system to enter S0i3. We are currently not able to resume controllers once they are suspended and thus can only suspend once.
- **Debugging tools:** Hangs/crashes during suspend-to-idle are hard to debug, as the machine is effectively unresponsive. Better tooling makes it much easier to narrow down issues, especially on new hardware.
- **Testing on other hardware:** Bringing up S0i3 entry on laptops other than the Framework, which tends to surface new issues.

#### Progress

Suspend-to-idle loop and hangs:

- Working on cleaner wake event reporting when suspended to idle, building on the prototype at [D54410 - acpi: Implement suspend-to-idle loop](https://reviews.freebsd.org/D54410).
- Working on getting [PR #71 - acpi_cpu: No longer disable idle during suspend](https://ron-dev.freebsd.org/FreeBSD/src/pulls/71) and [PR #72 - acpi: Use DELAY() when sleeping while clock suspended](https://ron-dev.freebsd.org/FreeBSD/src/pulls/72) merged. PR #71 supersedes [D60649 - acpi_cpu: Make disabling idle during suspend sysctl](https://reviews.freebsd.org/D60649).
- Cleaning up the fixes for Wayland client (e.g. Kitty) hangs, both on the FreeBSD side and the Kitty side.
- Looking into why the scheduler patch no longer seems to be needed.

Device suspend for S0i3:

- [D60540 - thunderbolt: NHI resume routine](https://reviews.freebsd.org/D60540) is still under review. This is a stopgap to enable re-suspending of USB4 controllers.

Debugging tools:

- Committed `fcaea1200aad` from [D61134 - acpi: Implement debug.acpi.suspend_bounce for suspend-to-idle](https://reviews.freebsd.org/D61134). This makes it easier to narrow down issues when testing on new systems.
- Trying to get watchdog (`amdsbwd`) to reset the system if it hangs during suspend-to-idle.
- Trying to get `dmesg` to be persistent across resets from suspend-to-idle, so that the logs leading up to a hang can be recovered.

Other hardware:

- Work debugging S0i3 entry on the Dell AMD Ryzen AI 5 PRO 435 w/ Radeon 840M and the Lenovo T14 Gen 4.
- Continued debugging iwlwifi deadlock which sometimes occurs on resume, requiring reboot to get WiFi working again. The issue has been identified and a fix has been made, but this needs to be cleaned up and made into a revision.
