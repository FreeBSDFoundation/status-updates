## **Reporting Period:** 2026-10-14 - 2026-10-26

### Project: Vision Accessibility
#### **Overall Status:** On Track
#### **Summary**

Vision Accessibility is a project focused on improving visual accessibility in FreeBSD by documenting, developing, and integrating assistive technologies for blind and visually impaired users.

Work in progress: Milestone 2.
Create high-contrast themes for the TUI utilities in the FreeBSD BASE system, with an option to select a high-contrast theme directly during OS installation.

**Last week's work**:

I tested the Apex connected as "Terminal for Screen Reader" in "USB Serial" mode and collected all my notes in a blog post: [Exploring the HumanWare BrailleNote Apex with FreeBSD](https://alfonsosiciliano.gitlab.io/posts/2026-10-15-freebsd-apex.html).

Then I switched to "USB Client" mode and collected all my notes in another blog post: [HumanWare BrailleNote Apex and FreeBSD via USB](https://alfonsosiciliano.gitlab.io/posts/2026-10-26-freebsd-usb-apex.html).

In both modes, it is possible to send and receive bytes from FreeBSD.
I encountered some issues when sending bytes to raise the pins on the Apex's Braille cells. Further investigation is needed to better understand the protocol.

I have gathered all the information I need to write a device driver. The relevant details are described in the "Comparing USB Serial and USB Client" table in the second post.
It should probably be possible to write a single driver supporting both modes:

 - Microsoft VID 0x045e, Windows Sync PID 0x00ce, iSerial 28171312-0031-0000-0000-000000000000
 - HumanWare VID 0x1c71, BrailleNote Apex (Braille Terminal mode) PID 0xc004

The only remaining task is to test and evaluate Bluetooth communication as well.

 - Milestone 1: Created the Accessibility Handbook, documenting the current assistive technologies for visual accessibility available in FreeBSD, both in the BASE system and the Ports Collection.

- Milestone 2: Improved existing themes and created new themes for TUI utilities.

### Project: KDE Installer Dialogs
#### **Overall Status:** Delayed
#### **Summary**

The goal is to allow users to install KDE at the end of the bsdinstall process through a series of dialog-based interfaces.
After rebooting, SDDM starts automatically, allowing the user to log in to the graphical environment.

Project: [repository](https://gitlab.com/alfix/kde-installer-dialogs).

**This week's work:**

I was waiting for the new ports to be added before testing and submitting the new script for bsdinstall.
However, the ports have stalled on Bugzilla, 

 - x11/bsdinstall-desktop [PR298402](https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=298402)
 - graphics/bsdinstall-gpu [PR298413](https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=298413)
 - x11/bsdinstall-de [PR298442](https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=298442)
 - x11/bsdinstall-dm [PR298455](https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=298455)

So this week I started testing the new [desktop script](https://gitlab.com/alfix/kde-installer-dialogs/-/blob/main/desktop.ports) locally on my laptop by building ISOs.

I encountered some issues because the ports handle their own environment variables.
For example, I wanted to configure files under $BSDINSTALL_CHROOT/etc/..., but this is actually incorrect because pkg is already invoked with BSDINSTALL_CHROOT as its chroot directory.
Therefore, the ports should not prepend BSDINSTALL_CHROOT to the paths they configure.

**Last week's work**:

I have completed the design and implementation of the theming functionality for bsddialog.
The changelog is included in the previous report.
I have started the testing phase, mainly focusing on the library.
This will be followed by testing the port and then a make buildworld before importing the new version into BASE.

This week, I mainly focused on using the HumanWare BrailleNote Apex Braille display, since the charger was finally delivered.
I wanted to test the device and start using it.
This task is actually planned for the upcoming milestones, but since designing the Braille subsystem is quite complex, I decided to start experimenting with the device and gradually work on the design already now.

Since both the keys (input, writing) and the dots (reading, output) use Braille, I had to study Braille again.
In particular, I used [LearnBraille](https://gitlab.com/-/snippets/6065143), a Lua script I wrote which uses /devel/liblouis to provide a quiz for practicing Braille characters.
For writing, I used the word processor included with the Apex.
I configured English Grade 1 because it was initially set to English Grade 2, which uses contracted words. With Grade 1, words are written normally in English.

I then connected the Apex to a monitor through its VGA port, which allowed me to use and better understand the device's functionality.

Finally, I used the "Screen Reader Terminal" functionality, which turns the device into a simple Braille display that can be connected as a Braille peripheral to another device.
I connected it to my FreeBSD 16.0-CURRENT laptop. The display is recognized and managed by uipaq(4), which makes sense since the Apex runs Windows CE 6.0.
I have so far managed to send data to the device, including a simple "Hello World, FreeBSD!" message displayed in Braille, and I have also managed to receive the characters typed on the Apex keyboard on FreeBSD.
In particular, for each character, a byte is sent where each bit represents a Braille dot.

I have also started writing a blog post to document the notes and results of these first tests.
