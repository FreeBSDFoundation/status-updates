### Project: KDE installer dialogs
#### **Overall Status:** Delayed
#### **Summary**

The goal is to allow users to install KDE at the end of the bsdinstall process through a series of dialog-based interfaces. After rebooting, SDDM starts automatically, allowing the user to log in to the graphical environment.

Work in Progress: [repository](https://gitlab.com/alfix/kde-installer-dialogs).

**This week's work:**

This week, I completed the draft of the new script locally. It is completely different from the previous script.

The current draft of the script is approximately 100 lines of code. The idea is to install ports providing utilities for building the menus (a new addition this week), while the ports' flavors perform the configuration using `pkg-post-install.lua(5)` (the rationale for this approach is explained in last week's report).

The draft for the ports/flavors has also been improved.
The new ports should be:

 - bsdinstall-desktop:
     - bsdinstall-desktop utility for checks (bsdinstall-desktop checks) and users (bsdinstall-desktop usersmenu).
     - A Lua library for the pkg-post-install.lua(5) scripts of the other ports. For example, a Lua equivalent of sysrc(8).
 - bsdinstall-gpu:
     - bsdinstall-gpu utility for the GPU menus (bsdinstall-gpu menu). It also provides GPU autodetection.
     - Flavors: amd, drm, intel, nv304, nv340, nv390, nv470, nv580, nv595, nv610, nvaddons, nvoptimus, radeon, scfb, vbox, vesa, vmware.
 - bsdinstall-displaymanager:
     - bsdinstall-displaymanager utility for the display manager menu (bsdinstall-displaymanager menu).
     - Flavors: sddm, ly.

A new review will be opened because review D56167 for the previous script will be closed. The new script is completely different, so the comments and discussions from the previous review are no longer relevant or add any value.

Commits in the [GitLab repository](https://gitlab.com/alfix/kde-installer-dialogs/-/commits/main?message=The%20FreeBSD%20Foundation&committed_after=2026-08-17&committed_before=2026-08-25).

Work in Progress: [repository](https://gitlab.com/alfix/kde-installer-dialogs).

**Last week's work:**

During this week, I updated the review of the desktop script for bsdinstall as suggested. However, the script will be rewritten to move many of its components into new ports.

This week, I studied and experimented with several possible approaches. The solution is to create new ports with flavors.

For example, a bsdinstall-nvidia port with flavors/packages: bsdinstall-nvidia-610, bsdinstall-nvidia-595, and so on.
Each package is actually a metaport that installs the corresponding package.
For example, bsdinstall-nvidia-340 will install nvidia-driver-340 as dependency, and pkg-post-install-lua(5) will configure the driver so that it is ready for the system's first boot.

I chose pkg-post-install-lua(5) instead of pkg-post-install(5) because, if future requirements make it necessary to use pkg-trigger(5) instead of pkg-post-install in sh, it will be easier to switch, since triggers currently support only Lua.

Currently, I have local drafts for the following ports: bsdinstall-gpu, bsdinstall-nvidia, bsdinstall-displaymanager.

The commits are available in the [GitLab repository](https://gitlab.com/alfix/kde-installer-dialogs/-/commits/main?message=The%20FreeBSD%20Foundation&committed_after=2026-08-10&committed_before=2026-08-18&page_size=100). The script currently in progress is desktop.port in the repository.
