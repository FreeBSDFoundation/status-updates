## **Reporting Period:** 2026-10-07 - 2026-10-13

### Project: Improve OpenJDK on FreeBSD
#### **Overall Status:** On Track
#### **Summary**

[openjdk/bsd-port #16] was flagged by the upstream reviewers that they
preferred it submitted directly as a PR to mainline instead. That's of course
fine for us. Resubmitted as [openjdk/jdk #33248].

Likewise, [openjdk/bsd-port #19] was also requested to move to mainline, and
has been resubmitted as [openjdk/jdk #33334].

[openjdk/bsd-port #17] was not as well baked as I thought. So had to submit a
number of follow up patches to make it pass the test suite.

While the upstream `bsd-port` branch is not expected to build for any of the
BSDs yet, the workflows for building and testing the other platforms should not
break.

The PR should be ok now, and has been resubmitted for review.

Response to [openjdk/bsd-port #18] on the [nio-dev@] list, suggest that
upstream prefers that we split the BSD code off into a `BsdNativeDispatcher`
class instead. I have not had time to look into that yet, but have scheduled
this for the next task.

- Open PR's:
  - [openjdk/jdk #33334] BSD supports `posix_fadvise` (review accepted, waiting for tests before integrating)
  - [openjdk/bsd-port #17] Fix debugd connect test on FreeBSD. (review in progress, serviceability-dev)
  - [openjdk/bsd-port #18] Add BSD support for `libnio/fs/UnixNativeDispatcher` (addressing review requests, [nio-dev@])
- Completed and closed PR's:
  - [openjdk/bsd-port #16] Clamp `SO_LINGER` to valid range on BSD. (closed, [migrate to mainline], [net-dev@])

  - [openjdk/jdk #33248] 8393721: Reduce max `SO_LINGER` value for BSD (mainline, integrated)
